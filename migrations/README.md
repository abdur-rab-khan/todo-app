# Database Migrations (Alembic)

Schema changes go through Alembic — never `SQLModel.metadata.create_all()`.
Config lives in `alembic.ini`; the DB URL is built from `.env` in
`migrations/env.py`. Run everything from the project root.

## Workflow

```bash
docker compose up -d

# 1. Change your models, then generate a migration
uv run alembic revision --autogenerate -m "add due_date to todo"

# 2. Review the new file in migrations/versions/

# 3. Apply it
uv run alembic upgrade head
```

## Commands

| Command | Does |
| --- | --- |
| `uv run alembic revision --autogenerate -m "msg"` | Create a migration from model changes |
| `uv run alembic upgrade head` | Apply all pending migrations |
| `uv run alembic downgrade -1` | Undo the last migration |
| `uv run alembic current` | Show the revision the DB is on |
| `uv run alembic history` | List all revisions |
| `uv run alembic check` | Fail if models and DB are out of sync (use in CI) |
| `uv run alembic stamp head` | Mark the DB as current without running anything (baseline) |

## Rules

1. **Review every autogenerated file** — renames show up as drop + add, which loses data.
2. **Never edit an applied migration** — add a new one instead.
3. **One logical change per migration**, committed alongside the model change.
4. `downgrade()` should actually work.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `connection refused` | `docker compose up -d` |
| `No 'script_location' key found` | Run from the project root |
| `Multiple head revisions are present` | `uv run alembic merge -m "merge heads" <rev1> <rev2>` |
| Autogenerate writes an empty file | Models aren't imported in `env.py`, or the DB already matches |
